# Initial Setup — Skate Journal

> **사용법**: 프로젝트 폴더에서 첫 세션을 열고 "initialsetup.md 읽고 순서대로 진행해줘"라고 말한다.
> 이 파일은 한 번만 쓰는 지시서다. AGENTS.md에서 참조하지 않는다. 설정이 끝나면 마지막 단계에서 정리한다.

## 0. 원칙
- 각 단계를 끝낼 때마다 무엇을 했는지 한 줄로 알려준다.
- 결정이 필요한 단계에서는 멈추고 묻는다. 내 답을 받기 전에 다음 단계로 넘어가지 않는다.
- 이 단계에서는 디자인 작업을 하지 않는다. 구조, 문서, 결정, 빈 스캐폴딩까지만.

## 1. 구조 확인
아래 파일이 있는지 확인하고, 없으면 만든다.
```
AGENTS.md                   매 세션 읽히는 짧은 지침 (유일한 지침 파일)
docs/spec.md                콘텐츠 구성, 기능, 스키마
docs/roadmap.md             마일스톤과 현재 상태
docs/design/direction.md    디자인 원칙과 열린 질문
docs/design/references.md   디자인 레퍼런스
DECISIONS.md                결정 기록
LATER.md                    범위 밖 아이디어
```
- `git init` 후 첫 커밋한다 (이미 저장소면 생략).

## 2. 도구 연결 (AGENTS.md 하나만 유지)
- Codex: `AGENTS.md`를 그대로 읽는다. 추가 작업 없음.
- Claude Code: 내용을 복제하지 말고 루트에 `CLAUDE.md`를 만들어 아래 한 줄만 넣는다.
  ```
  @AGENTS.md
  ```
  이후 지침 수정은 항상 `AGENTS.md`에서만 한다.

## 3. 문서 읽고 질문하기
- `AGENTS.md`, `docs/spec.md`, `docs/roadmap.md`, `docs/design/direction.md`를 읽는다.
- 모호하거나 빠진 점을 질문 목록(최대 7개)으로 정리해 나에게 묻는다.
- 반드시 포함할 질문:
  1. 프레임워크: Astro vs Next.js
  2. 미디어 저장 위치와 영상 용량 (원본을 저장소에 둘지, 외부 스토리지에 둘지)
  3. 모바일에서 세션을 빠르게 입력하는 방법
  4. 공개 페이지 배포 위치와 도메인
  5. 마일스톤별 목표일과 주당 투입 가능 시간
- 답을 받으면 `DECISIONS.md`에 기록하고, `docs/spec.md`의 기술 스택 절과 `docs/roadmap.md`의 목표일을 갱신한다.

## 4. 스캐폴딩
- 확정된 스택으로 빈 프로젝트를 만든다 (실행되는 빈 페이지까지만).
- `docs/spec.md`의 폴더 구조대로 `content/`와 `media/`를 만든다.
- `.gitignore`를 만든다. 대용량 미디어를 저장소 밖에 두기로 했다면 `media/`를 제외한다.
- `AGENTS.md`의 "명령어" 절에 설치, 실행, 빌드 명령을 채운다.
- 커밋한다.

## 5. 연결 구조 확인 (스타일 없이)
- 샘플 콘텐츠를 만든다: 세션 1, 글 1, 장비 1, 스팟 1, 레퍼런스 3. 내용은 자리표시용으로 짧게.
- 글 페이지에서 연결된 세션, 장비, 스팟, 레퍼런스가 링크로 보이는지 확인한다.
- `visibility: private`인 콘텐츠가 빌드 결과에 포함되지 않는지 확인한다.
- 스키마에서 바꿀 점이 보이면 정리해 보여주고 묻는다.

## 6. 마무리
- `docs/roadmap.md`에서 M0을 완료로, 현재 단계를 M1로 바꾼다.
- 이 파일을 `docs/archive/initialsetup.md`로 옮긴다.
- 커밋하고, 다음 세션에서 할 일(M1 레퍼런스 수집)을 3줄로 리포트한다.
